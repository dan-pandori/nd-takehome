## `nd2lean.py`'s BOTE `.elim` makes a Lean pass insufficient on its own (ds-rendering, 2026-09-23)

**Question.** Should `nd2lean.py` render BOTE as something that cannot resolve to `Not.elim` — e.g. `False.elim (nA : False)` with the ascription, or `absurd`? And should NEGE be ascribed likewise?

**What I found.** Over 949,568 distinct (theorem, Lean text) pairs checked by both checkers in this run, Lean and `nd_verify` disagree on 241 (0.025%), **all in one direction: Lean accepts, `nd_verify` rejects.** `nd_verify` never once accepted something Lean rejected. 93% of the 241 trace to one root cause — Lean's `¬a` is *definitionally* `a → False`:

- **186 BOTE.** `nd2lean.py:135` renders BOTE as `{name}.elim`. That is `False.elim : False → b` when the cited line is `F`, but **`Not.elim : ¬a → a → b`** when the cited line is `¬a` — so it typechecks whenever the goal happens to be `a → …`. ND's BOTE requires the cited line to be `F`. Example (`dsr-c0`): `N4 | | ( Q > ( R > P ) ) : BOTE N1` with `N1 = ( ~ Q )` renders `have n36 : ( Q → ( R → P ) ) := n31.elim`, which Lean accepts and which is not ex falso at all.
- **38 NEGE.** `:134` renders `{b} {a}`; `nB : ¬(A → False)` applied to `nA : ¬A` also typechecks.

**Why it matters beyond this run.** This is the unmodified checker of record's own convention, so it applies to anything in this repo that treats "Lean accepted it" as sufficient. **It was harmless here only because acceptance is the conjunction Lean ∧ `nd_verify`** — all 241 were rejected and no counted proof in this run is affected. Anywhere the conjunction is *not* enforced, this is a live soundness hole.

**My default (taken).** Leave `nd2lean.py` unmodified — the take-home's rules require that, and the conjunction already closes the hole. I report the agreement number (99.9746%) with the direction and the cause rather than treating the 241 as noise. `dsr_disagree.py` reproduces all of it.

**Second-order finding worth a look.** The *rendering* changes how often Lean is fooled, per 100k pairs checked: R1 6.0, C0 6.3, R4 31.3, R2 46.4, **R3 115.2 — 18× the control.** R3 (`lean_seq_nofml`) drops the stated formula on exactly `IMPE ANDE1 ANDE2 NEGE R`, so a misapplied rule has no stated formula for the decoder to contradict. **A rendering that hides formulas measurably weakens Lean as an independent check** — a cost of R3 that none of the accuracy numbers show.
