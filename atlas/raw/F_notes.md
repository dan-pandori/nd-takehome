## Pool / protocol verification
- **dev1108:** `dan_best-state:data/bs/dev1108.jsonl` is identical, in the same order, to the sha1(key)-parity-even half of `data/ladder/transfer.jsonl` (blob `e0524d0a`, the same blob Robbie's harness used).
- **holdout250:** the set is identical to the first 250 odd-parity theorems sorted by sha1("passk:"+key), as in Robbie's `passk.py`.
- `pod/bs/read.sh` reads dev at k 64, T 0.8: the fork "dev metric" is Robbie's definition (same half, k, T).
- **Temperature:** every fork read-out is T 0.8, from its args file (textbook72: `state_eval.py --k 256 --temperature 0.8 --max_steps 96 --max_action 512`). Robbie's reads are also T 0.8. TTRL / sample-more / targets-only rows are T 1.0 and train on dev statements. They have their own non-comparable group.
- **Checker:**
  - Fork (state_eval → `lean_judge`): Lean alone.
  - Robbie's lean cells: Lean gate then nd_verify.
  - Robbie's abs cells: nd_verify alone.
  - Robbie's state recipes: Lean alone.
  - The textbook72 run measured Lean ∧ nd_verify = Lean on all 12 SN reads, so lean_only and lean_and_ndverify are near-equivalent. They are kept as separate groups anyway.
- **Seeds:** fork 2–4 model seeds, sample seed 0 except trajectory x1 / rfc x1 (in `judge`); Robbie 3.

## Apples-to-apples groups (`apples_group` = pool|k|T|checker)
- `textbook72|k256|T0.8|lean_only`: all fork families plus none of Robbie's.
- `…|lean_and_ndverify`: Robbie lean factorial and scale.
- `…|nd_verify`: Robbie abs.
- `dev1108|k64|T0.8|lean_only`: fork families plus Robbie's state recipes (198/201/204/207 SN/SH/C0). This is the cleanest fork↔Robbie overlap on a shared checker.
- pass@k rows each carry their own k.

Cross-format comparisons share pool, k and T, but the interface differs:
- Fork: state env, max_steps 96.
- Robbie: whole-proof lean_seq, max_new 512.

Example on textbook72: best-9.56M-cap6 T1 (state) solves 37.3 of 72 vs Robbie lean-best-leon c005 (lean_seq) 31.3. The data, params and recipe are matched, so the gap is format plus RL algorithm, confounded.

Fork lean_seq models (C0 cap 6, K12 cap 12) were **never** scored on textbook72, dev1108 or holdout250.

## Re-score recommendation (not run)
**Re-score C0 (3.2M lean_seq, cap-6 155k data) T1 on all three pools:** `hf://buckets/dan-pandori/nd-rl/ds-generator/ckpts/ladder/la_T1_c0_s{0,1}_r8.pt`.
- Frozen Stage-1 is optional: `lean-format/ckpts/lf/stage1_a1_seq_s{0,1}.pt`.
- What it buys: the same format, data and size class as Robbie's `lean-naive-{ei,leon}` cells, so fork-ladder EI vs Robbie's RL is compared format-for-format. Against SN-v2 cap6 it isolates the interface (whole-proof vs state).

On a pod at `dan_best-state`, for s in 0 1:
```
python3 eval_set.py --ckpt ckpts/inh/T1_C0_s$s.pt --in data/bs/textbook72.jsonl --k 256 --temperature 0.8 --seed 0 --batch 2048 --lenfield reference_lines --out artifacts/bs/eval/T1_C0_s${s}__tb72.jsonl --summary artifacts/bs/eval/T1_C0_s${s}__tb72.json
python3 eval_set.py ... --in data/bs/dev1108.jsonl   --k 64  ... --lenfield n_lines (→ __dev)
python3 eval_set.py ... --in data/bs/holdout250.jsonl --k 256 ... --lenfield n_lines (→ __h250)
```
Caveat: `eval_set` uses `sample.generate` max_new 400, not Robbie's 512. Report the truncation share, or pass 512.

Cost: ≈153k samples per ckpt. Comparable state reads took 100 s / 416 s / ~400 s for a 3.2M model. Estimate ≈12 min per ckpt, so **≈30–40 A40 GPU-minutes** for both seeds including Lean judging and setup. Adding K12 (`state-cap12/ckpts/ladder/la_T1_K12_s{0,1}_r8.pt`) for the cap-12 pairing with SN12 would cost about +30 min.
