## textbook72 numbers across runs (289 reads, `c4_tb72_table.tsv`)

- **Pool.** Every read across textbook72, best-state, trajectory and trajectory-cap6 has the same 72 (name, prompt) pairs: hash `8789589d21`, which equals `data/bs/textbook72.jsonl` (md5 `90355c36`) and `eval_only` dev + train. Every read uses 256 attempts per problem, T 0.8.
- **Settings that differ.**
  - Batch: 4096 in the textbook72 run, 2048 elsewhere.
  - textbook72 also has a diagnostic read at `max_action` 1024.
  - All reads use the same checker (Lean alone, post-09-27).
- **"37 of 72" is per seed (s0).** The per-seed counts are 37 / 38 / 36 / 38 and the union is 46. The week-in-review's "36–38" and "51–52" are per-seed ranges and correct.
- **Same checkpoint read twice: 133 pairs.**
  - Trajectory x0 / x1 sample seeds give 132 pairs over 66 checkpoints. Differences are at most 4 problems, with 2.0 flips on average. 7 / 133 have |z| > 1.96 (6.6 expected) and sd(z) is 1.11, so they are consistent with binomial redraw.
  - The textbook72 a512 vs a1024 pair is identical (37 / 37). It uses the same seed, so it is not an independent draw.
- **Contamination.** `textbook_3ed45280` (`P ∨ Q, ¬P ⊢ Q`) is a premise-order permutation of a K12 theorem. My key reproduces this one hit. It affects both cap-12 arms equally (≤ 1 / 72).

## Checks

- Accounting: 12 / 12 best-arm tb72 dumps have a Lean-accepted prompt set equal to the solved rows.
- Lean, own driver, best arms: **96 / 96** literal texts accepted (8 per arm-seed).
- Lean, ours arms: there are no literal texts, so I checked 48 / 48 `nd2lean` renderings of stored ND proofs (4 per checkpoint).
- Negative controls: 0 / 144 accepted in each of four kinds (other theorem, negated goal, final `exact` dropped, `exact sorry`).

## Rating: **holds with caveats**

- The after-RL win at both caps is real, beyond the observed-sd MDDs, and replicated by independent runs of the same recipes.
- **Strongest objection.** It is a 3× larger model using 1.5–1.9× the ladder GPU time (same GPU class), so the win cannot be attributed to the recipe as opposed to scale or compute.
- **Suggested wording:** "After the same RL ladder (equal attempts), Robbie's 9.6 M recipe solves 51–52 (cap 12) and 33–40 (cap 6) of 72, against our 3.2 M model's 36–38 and 16–22. This replicates in independent training runs. It is not compute-matched: about 3× the parameters and 1.5–1.9× the ladder GPU time."
- **Recommended re-sampling:** none for the counts. For attribution, a compute-matched ours ladder: the 3.2 M SN-cap12 / SN-v2 Stage-1 checkpoints at 2× ladder attempts on A40, read on textbook72 at k 256.
