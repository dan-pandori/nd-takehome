# C2: a proof-state base reaches the survivors (support-state, state-readouts)

**Claim as written.** "A proof-state base reaches 28 of the 29 with no RL" (nd-rl
`2026-09-28-support-state-state-base-reaches-survivors`), and "Seeing the state is what does it, not the environment's
naming" (`2026-09-30-state-readouts-state-not-naming-reaches-survivors`; the S model reaches 25–28).

## Attacks
- **(a) Attempts.** The per-theorem cap is the same as for the WP base (≤ 200k at T0.8, then ≤ 200k at T1.0). Unlike
  the WP base, the state arms stop after 5 hits. Most survivors are reached far earlier than the cap: SN s0 reaches 26
  within the first 10,000 attempts. So "reaches" is not an artefact of a larger budget. One state attempt is one full
  episode (one action per step), not one resampled step: a failed action ends the attempt
  (`state_sample.py` l.78–85).
- **(b) Training match.** Confirmed: same data, same number of steps, same proofs per step, same architecture.
- **(c) Does the environment do the work?** I read `state_env.py`. The environment:
  - is purely syntactic;
  - has no type checker;
  - never auto-closes a goal;
  - never retries an action.

  It does supply the box-closing tokens and the Or.elim second-branch opener (including that branch's binder
  formula). It also rejects an `exact` that does not match the goal, which ends the attempt early. These count as
  interface help: the WP model has to write those tokens itself, and 36.5 % of its samples fail the grammar. They do not
  supply proof content.

  The assembled `lean_seq` text is Lean-checked as a whole. My own driver accepted **48/48** random accepted survivor
  texts (12 each from SN s0, SN s1, S s0 and S s1; out of 1,337 / 948 / 1,528 / 2,049 distinct). Every prompt is
  verbatim a `theorems.jsonl` survivor statement. It rejected **48/48** negative controls.
- **(d) "Not naming".**
  - S vs SN is n = 2 seeds per arm, with reach 28/25 vs 28/28. `NOISE_FLOOR.md` (l.55) notes that an n = 2 vs n = 2
    comparison can never reach p < 0.05. The pre-registered 5-theorem margin is not exceeded, so the result is "no
    naming effect detected", not "no naming effect".
  - Per-theorem rates do differ. Paired on the same theorem and seed, S/SN p̂ has median ratio **0.16** on seed 0
    (S higher on only 4 of 24) and 0.69 on seed 1. Reached within 10k: S 21/20 vs SN 26/23.
  - The S arms also used 2.5× and 1.8× SN's attempts.
- **The bigger wording issue.** S differs from the WP base in more than seeing the state. It also has the step
  interface: per-action generation, environment-rendered structure, and early termination. No arm has the steps
  without the state. So "seeing the state" cannot be separated from "the step interface".
- **Leakage.** 0 survivors are in the training set or in `rl_targets` (C1, own canonicaliser).

## Rating
- **"Reaches 28 of 29 with no RL": solid.** Confirmed per seed, from rows and dumps, and Lean-checked.
- **"Seeing the state, not naming": holds with caveats, weaker than stated.** "State" stands for the whole state/step
  interface. The naming null is about reach at n = 2, and naming changes the per-theorem rate by up to about 6×.

**Suggested wording.** "A base trained on the same data and steps to act through a proof-state step interface
reaches 28/29 (both seeds; 23–26 within 10k attempts) with no RL. A variant that writes its own names reaches 28 and
25: no naming effect on reach at n = 2, though its per-theorem rates are lower."
